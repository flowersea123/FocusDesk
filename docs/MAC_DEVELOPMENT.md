# Mac 本机开发与设备模拟

本轮范围是 macOS 源码开发和软件显示模拟，不包含原生菜单栏应用、签名或 DMG 安装包。现有 Windows 安装与固件入口保留。

## 第一次启动

需要 Node.js 24 或更新版本。以下命令在仓库根目录执行：

```sh
npm --prefix frontend ci
npm run dev
```

开发入口会启动真实 Hub 和 Vite 页面服务：

| 页面或服务 | 默认地址 | 用途 |
| --- | --- | --- |
| Dashboard | http://127.0.0.1:5173/ | 添加、修改、完成任务，开始专注，填写建议 |
| 设备模拟屏 | http://127.0.0.1:5173/simulator | 接收保存后的设备显示快照并画出像素 |
| Hub | http://127.0.0.1:8787 | 真实读取/保存业务与设备接口 |

两个服务默认只监听本机。页面请求通过开发代理访问 Hub，保留本机同源写入规则。模拟器直接读取 `/api/v1/display-snapshot`，不通过主页设计预览中转、不使用另一套任务存储。

任务保存在忽略的 `backend/data/tasks.json`。文件不存在时才复制 `tasks.example.json`；已有文件（包括无效文件）不会被示例覆盖。无效文件会报错，需要检查原数据。示例日期是固定日期，产品尚未自动按天归档或切换任务。

前端支持热更新。修改 `backend/server.ts`、`backend/src/*.ts` 或共享 `contracts/*.ts` 时，开发入口停止并重启自己启动的 Hub，再刷新页面。请先保存网页编辑草稿。后端修改后若暂时无法启动，会保留开发页面并打印错误；修正源码再次保存即可重试。Ctrl+C 停止 UI 与 Hub，不停止其他程序。

端口被占用时会报错。可明确选择其他端口或隔离任务文件：

```sh
npm run dev -- --port 8790 --ui-port 5174 --data .cache/my-development/tasks.json
```

`--open` 可自动打开 Dashboard；`--no-watch` 禁止后端源码监视，主要用于隔离测试。前端 Vite 自身的开发更新仍然可用。

## 如何验证一次修改

1. 在 Dashboard 添加一条英文任务并保存。
2. 打开模拟屏，确认显示真实任务，而非主页的“多任务示例”。未保存草稿不会进入模拟屏。
3. 修改文字、勾选完成、开始/结束专注或修改建议，再保存并观察模拟屏。
4. 用超过五条任务、长标题、空列表、全部完成和两行建议检查显示边界。
5. 切换到设备节奏，检查等待刷新与版本未变化时不重复绘制。
6. 模拟断网，再修改并保存任务；模拟屏应保留旧画面。恢复连接后观察新内容按所选节奏更新。

主页右侧现有 HTML/CSS 设计预览仍保留，用于编辑草稿。独立模拟屏则执行真实 Hub 发送的绘图指令，使用共享位图字形、400×300 分辨率和四色调色板。中文建议可在网页保存，但设备协议生成的是英文不支持提示，模拟屏也应如此显示。

## 两种运行方式

- **快速检查**：缩短读取等待，便于修改排版后立即查看。它不代表硬件刷新速度。
- **设备节奏**：约30秒读取一次，相邻显示尝试之间保留60秒保护，读取失败逐步退避。读取成功和画面实际应用分别记录；同一已显示版本不重复绘制。手动读取不会取消刷新保护。

页面可放大查看位图和导出 PNG。放大与 PNG 输出不改变设备400×300像素数据。浏览器页面在后台时可能受到系统计时节流，因此模拟定时不是实时硬件计时测量。

## 修改哪些位置

| 内容 | 位置 | 在 Mac 上怎么验证 |
| --- | --- | --- |
| Dashboard交互 | `frontend/src/` | 页面操作、前端测试 |
| 任务业务、专注和保存 | `backend/src/` | 真实开发Hub、后端/HTTP测试 |
| 设备筛选、排序、排版、截断 | `contracts/display-snapshot.ts` | 模拟屏、共享布局测试、原生像素比对 |
| 模拟器自身 | `frontend/src/DeviceSimulator.tsx`、`frontend/src/simulator/` | 协议、状态、交互测试 |
| 配网与固件显示执行 | `firmware/` | 可运行主机逻辑/渲染检查，仍需后续真机确认 |

修改设备布局时仍应更新显示 revision 前缀，使真实设备能识别“数据没变但排版已变”。开发服务自动刷新页面并不能代替这个设备协议要求。新增字体/指令或改驱动还需要配套更新固件。

## 验证命令

```sh
npm test
npm run test:frontend
npm run test:integration
npm run test:development
npm run build
npm run test:display-host
```

最后一项需要本机 C++ 编译器和首次下载固定版本的官方绘图库。它使用实际固件解析器、显示驱动及官方 Adafruit GFX，而非重复浏览器绘图实现。固定版本、缓存和详细验证边界见 [固件主机模拟](firmware/HOST_SIMULATION.md)。

生产构建也可在 Mac 上运行：先关闭开发服务，执行 `npm run build`、`npm start`，然后通过8787端口访问主页与 `/simulator`。任务文件需已经由开发入口初始化，或按现有源码启动流程准备。当前 macOS 数据锁使用系统 `lockf`，锁随进程退出自动释放。任务目录中留下的空 `.focusdesk-data-*.lock` 文件是稳定锁载体，不代表仍在运行，不应手动清理正在使用的锁文件。

## 能确认与不能确认的内容

软件链路可以确认保存、版本冲突、任务筛选、文字截断、位图像素、专注状态、轮询节奏和读取失败时保留画面。原生主机校验可独立比对固件绘图结果，并检查部分配网/存储状态机。

这不是完整 ESP32 指令集、无线射频或电子纸物理模型的仿真。手机真实配网、NVS实物断电行为、供电、GPIO接线、屏幕BUSY信号、刷新波形/耗时、残影、实体颜色、内存压力和长期稳定性仍需设备验收。模拟屏的“已绘制”仅指浏览器画布，不是物理设备回执。
