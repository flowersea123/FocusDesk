# Mac 固件主机校验与像素对照

这条开发路径用于在没有开发板时检查解析、排版和同步规则。网页模拟屏读取真实 Hub 的显示快照；本页的原生校验另外编译真实固件显示模块，与网页使用的 JavaScript 栅格逐像素比较。两者都不等于完整 ESP32 仿真或实物验收。

## 运行

需要 Node.js 24 或以上版本，以及 Mac 已安装的 Apple Command Line Tools（提供 `clang++`）。首次需要联网下载一份约 321 KiB 的固定版本图形库源码；不安装全局库，不下载 ESP32 工具链。

在仓库根目录运行：

```sh
npm run test:display-host
```

也可以直接运行 `node scripts/test-display-host.mjs`。脚本根据自身位置定位仓库，目录中有空格也可运行。需要选择其他现有编译器时，将 `CXX` 设置为编译器可执行文件的路径；它不是包含多个命令的 shell 字符串。

如果缺少编译器，先安装 Apple Command Line Tools：

```sh
xcode-select --install
```

这是用户单独执行的系统安装步骤，校验脚本只检测并提示，不会自行安装。

## 检查的内容

1. 下载并核对官方 Adafruit GFX 1.13.0 源码归档的 SHA-256，之后复用项目内缓存。每次校验从已核对的归档重新解压，保留官方许可。
2. 使用 `clang++ -std=c++17 -Wall -Wextra -Werror` 编译官方、未修改的 `Adafruit_GFX.cpp`，再链接仓库已有的 `v02_snapshot_test.cpp`、真实快照解析器、真实字体与 JD79668 显示驱动。
3. 运行现有 252 项快照检查，覆盖协议版本、绘图容量、坐标和字形边界、非法输入拒绝及字形像素。
4. 调用现有 `scripts/check-display-parity.mjs`：Hub 的共享布局生成 21 个合成场景，原生程序执行绘图，并从真实驱动发往 SPI 的 30,000 字节画布中恢复 120,000 个颜色索引，与 JavaScript 栅格逐个比较。
5. 运行另外五套现有纯 C++ 检查：配网解析/状态 83、配置事务 331、配置会话 81、Hub 响应校验 295、显示同步 107，共 897 项。

当前成功结果合计 **1,149 项原生检查，21 个场景各 120,000 像素一致**。场景包含空任务、全部完成、长标题、专注、十项任务、建议清空、长建议与非英文建议等。本命令使用合成数据，不读取个人任务、不需要运行 Hub。

## 为什么这是独立的显示对照

JavaScript 一侧使用 `contracts/display-snapshot.ts` 的共享布局和栅格。C++ 一侧使用固件已有解析器和显示命令执行器，文字和矩形由官方 Adafruit GFX 实现绘制，再经过真实面板驱动的四色像素打包。

`tests/firmware/mac-host/` 只适配 Arduino 的字符串类型、逐字节 `Print` 接口、数学辅助，以及既有测试提供的时钟/GPIO/SPI。没有复制 JavaScript 的字形绘制算法，也没有使用 `live_fakes/Adafruit_GFX.h` 的自写绘图实现。

新适配层给官方 GFX 基类换了宿主编译名称，并保留旧测试仅用于 `clear()` 的 `calls` 容器；不覆盖任何绘图方法。BusIO 两个头文件只有未使用类型的声明，不提供总线模拟。原来的测试文件和固件源文件不需要改动。

## 不覆盖的物理行为

这里没有执行 ESP32 指令、完整 Arduino Core 或统一 `.ino` 主循环，也没有连接实际 Wi-Fi、写入 Flash/NVS 或触碰串口。配网/NVS检查使用现成的测试替身验证状态和事务规则。

显示测试捕获模拟 SPI 调用；BUSY 引脚由测试桩返回就绪，时钟由测试代码推进。因此像素相同不能证明电气接线正确、面板真实色彩一致、波形/全刷时间正确或电源稳定，也不能证明运行堆内存、长时间稳定性和断电恢复已经实测。它不测量整机功耗或电池续航。

恢复实物开发时，仍需在固定 Core 3.3.12 和实际板卡配置下完整编译、通过 USB 手动上传，并由设备持有人检查配网、保存恢复、刷新和真实显示。Mac 主机检查通过不会自动升级为真机验收记录。
