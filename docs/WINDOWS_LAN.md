# FocusDesk Windows 局域网服务

此阶段提供可移动的服务文件夹，面向 Windows 10/11 和 Node.js 24+。不是安装包，不安装系统服务、不自动改防火墙，也还没有设备自动配网。Dashboard、最多三条英文任务、保存/冲突保护和固定 25 分钟专注逻辑保持原样。

## 普通用户开始使用

1. 将完整 FocusDesk-LAN 文件夹放在当前用户可写的位置，例如“文档”或桌面。保留文件夹内部结构，不需要放在 E 盘，也不需要原开发者目录或 npm 开发依赖。
2. 电脑需先安装 Node.js 24 或以上版本（[Windows LTS 下载](https://nodejs.org/)）；缺少或版本过旧时启动窗口会给出说明。这一运行时的集成留待后续安装包。
3. 双击文件夹中的 **Start FocusDesk.cmd**。浏览器会打开“设备连接”页面，页面中点“打开 Dashboard”管理任务。服务运行期间保持启动窗口开启；停止时在该窗口按 Ctrl+C，或关闭窗口。若浏览器未打开，按启动窗口显示的“Connection help”地址打开即可。
4. 服务电脑的默认入口为 `http://127.0.0.1:8787/`，连接说明页为 `http://127.0.0.1:8787/connect`。其他同局域网设备可用连接页列出的 Dashboard 地址查看内容，保持只读；任务编辑及专注控制仍仅允许服务电脑本机。

## 让电子纸连接

电脑与 ESP32 连接到可互访的同一网络，ESP32 使用 2.4 GHz Wi-Fi。连接页自动读取当前 Wi-Fi/以太网等 IPv4，多网卡时选与 ESP32 所在路由器对应的地址，复制“电子纸连接地址”。不要填 localhost、127.0.0.1 或监听通配值 0.0.0.0。

目前设备仍使用 Arduino IDE 人工配置：将复制的完整地址填入本地 `firmware/focusdesk_live/private_config.h` 的 `FOCUSDESK_API_URL`，例如 `http://192.168.1.20:8787/api/v1/daily-overview`。沿用原 Wi-Fi、开发板和接线设置，验证并手动上传。当前已烧录的设备若地址没变，无须为这次服务整理重新烧录；Agent 不操作串口或上传。便携服务目录不包含固件或私有 Wi-Fi 配置，使用已有固件工程操作设备。

## 电脑 IP、端口或网络变化

- IP 变化：服务默认监听全部 IPv4 网卡，通常不必重启；在服务电脑原本的 `/connect` 页面刷新即可看到新地址（页面也每 15 秒检查一次）。重新将新地址填入设备配置并验证/上传。只重启板卡或服务不会更新已烧录的设备地址。
- 端口占用：先检查是否已经开着一个 FocusDesk 窗口，优先关闭重复实例。确需换端口时，用记事本打开根目录 `focusdesk.config.json`，把 `port` 改为 1–65535 的整数，例如 8788，保存后重启。启动窗口和连接页会显示实际新端口；设备地址里的端口也要更新。不静默跳到随机端口。
- 正常配置为 `{ "host": "0.0.0.0", "port": 8787 }`。通常无需修改 host；只绑定某个局域网 IP 会失去本机 127.0.0.1 编辑入口。配置格式错误时明确报错，不重置文件或个人任务。

## 数据与迁移

任务和活动专注继续保存在文件夹内 `backend/data/tasks.json`，移动电脑时可把正在使用的整个服务文件夹一并复制。请先停止旧实例，以免迁移期间仍有保存；同一个任务文件只由一个服务实例使用。

给其他人分发的导出目录使用共享的合成演示任务，不复制开发机器的个人任务、活动专注、私有 Wi-Fi 配置或 .env。若要迁移自己的任务，应停止两端服务后，由用户将原 `backend/data/tasks.json` 单独备份并复制到新服务的同一路径；不要用新导出的演示文件覆盖唯一的个人数据副本。新服务读取显式文件日期，不自动改成当天；此行为沿用原实现。

## 无法从设备访问时

先在服务电脑打开 Dashboard，再从同一局域网的另一台电脑或手机打开连接页列出的 LAN Dashboard 地址。若本机能用但另一台设备不能用，检查 Wi-Fi/网线、Windows 专用网络访问许可、VPN、来宾网络或路由器客户端隔离；企业网络也可能禁止互访。Windows 弹出 Node.js 网络访问询问时，按实际使用场景允许专用网络即可，不要关闭整个防火墙。FocusDesk 不自动修改这些系统规则。

识别到某个 IP、读取 API 成功或网页显示专注都不等同于电子纸已连接/已同步，屏幕仍以用户观察为准。电脑休眠/关机时服务无法提供更新；设备恢复访问后按原轮询与刷新保护同步。

## 开发与导出

源项目仍支持原有命令；以下均在项目根目录运行，不假设具体盘符：

```powershell
npm run build
npm run package:lan
```

便携目录输出到 `.cache/releases/FocusDesk-LAN`，复制完整目录到目标电脑即可。再次导出需用一个新的目标目录：`npm run package:lan -- --output "新目录"`；已有输出始终拒绝覆盖。导出只复制已构建的 Dashboard 和最小 Backend/契约运行文件，不复制 node_modules 或前端源码；目标电脑不需要 npm install 或 npm run build。导出前请使用默认同源 HTTP 构建，不要将个人 VITE_API_BASE_URL 或 Mock 构建分发出去。

从源目录也可双击 Start FocusDesk.cmd，或运行 `npm run lan` / `npm run demo`。保留 `npm start` 作为仅本机入口。CLI 原有 `--host` / `--port` / `--data` / `--dist` 仍有效；参数优先于根配置，默认数据与 Dashboard 路径相对于程序自身，显式 --data/--dist 相对当前命令工作目录。

自动测试：`npm test`、`npm run test:frontend`、`npm run test:packaging`、构建后 `npm run test:integration`；固件主机测试沿用设备文档。本阶段不宣称已在所有 Windows 版本/网卡/防火墙组合或另一台实物电脑上验收。
